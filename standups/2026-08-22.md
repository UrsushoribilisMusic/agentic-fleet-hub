### TS-10: DO→Mac sync + headless NotebookLM integration

Built the full conflict-free queue plumbing from DO droplet to Mac pipeline:

**`tech-shorts/do_sync.py`** — stdlib-only DO intake API client:
- `claim_queued_job(base_url)` — atomic POST /api/jobs/claim (DO is single writer)
- `post_status(job_id, status, **fields)` — PATCH status + assets/youtube/x_post back to DO
- `get_job()`, `list_jobs()` — read-only polling
- `merge_job_local(job)` — upserts DO job into local jobs.json so pipeline.py works unchanged
- `open_tunnel()` / `close_tunnel()` — SSH port-forward to robotsales:8766 (no DNS needed yet)

**`tech-shorts/mac_worker.py`** — end-to-end orchestrator:
- `mac_worker.py run [--job ID] [--stage notebooklm|build|upload|post] [--dry-run]`
- `mac_worker.py watch [--interval N]` — daemon loop (claims → runs → reports, repeats)
- `mac_worker.py status` — side-by-side DO queue + local pipeline state
- Calls `notebooklm_driver.py run <job_id>` for Step 2 (stubs still in place; emits clear "fill CLICK_PROTOCOL.md" message and halts at that stage rather than crashing)
- Posts status back after each stage: raw_videos_ready → assembled → published

**`tech-shorts/ts10_worker.plist`** — launchd KeepAlive daemon spec:
- Runs `mac_worker.py watch --tunnel --interval 120`
- Logs to `~/Library/Logs/ts10_worker.{out,err}`
- Install: `cp ts10_worker.plist ~/Library/LaunchAgents/cc.flotilla.ts10-worker.plist && launchctl load ...`

**Tested:**
- `do_sync.py --tunnel health` → `API reachable: True` ✓

- `mac_worker.py --tunnel status` → DO + local state side-by-side ✓
- `mac_worker.py --tunnel run --dry-run` → "queue empty" when no queued jobs ✓
