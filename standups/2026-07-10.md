**Local-first default** (commit `58065cd4`): `_backend_plan()`'s "auto" mode tried hosted Mistral first whenever `MISTRAL_API_KEY` was present, contradicting ATF's own "local reasoning, no cloud dependency" pitch. Flipped default to local-Ministral-first; hosted still fully available via `--backend hosted`. Along the way fixed a bug where selecting a hosted model by its exact `list_models()`-listed name (`mistral-hosted:mistral-medium-3-5`) sent the whole prefixed string as the literal API model ID — Mistral's API rejected it with HTTP 400, silently falling back to local instead of erroring loudly.

**Model version bump** (commit `a48940b6`): `MINISTRAL_MODEL_PRIORITY` only had guessed tag names (`ministral-3b-latest`, etc.) that didn't match the real Ollama library tag (`ministral-3:8b`, pulled 2026-07-09 for the Robot Ross Mistral hackathon prep). Added the real tag as explicit top priority.

**HEAD request support** (commit `9666eb64`): `atf_local_server.py` 501'd any HEAD request (`BaseHTTPRequestHandler` default) — some browsers send HEAD as a prefetch/link-preview check before navigating, which could silently break the Wiki/Ledger link buttons.

**Fallback-chain fix after a real incident** (commit `cdb93328`): user asked what happens if you generate an SVG and ask ATF a question at the same time. I ran a live concurrency test to answer empirically — bad timing, it collided with the user's own real sketch-generation + chat test at the same moment. `ollama ps` showed the actual damage: **both `ministral-3:8b` and `MichelRosselli/apertus:8b-instruct-2509-q4_k_m` loaded simultaneously at 100% CPU** — because ATF's fallback chain, on a local-Ministral timeout (caused by the contention), silently fell through to a generic-Ollama stage that tried loading Apertus as a *second* model on the same already-saturated CPU-only laptop, compounding the failure instead of recovering from it. Apertus isn't used in the hackathon demo at all, so removed the auto-fallback to it entirely from the default/hosted/local backend plans — still reachable via explicit `--backend ollama` for anyone who wants it deliberately, just never auto-triggered by a timeout anymore.

## Robot Ross Control Center — ATF chat integration (Clau / Miguel session)

**Chat Q&A via ATF**: `_ask_ross()` now routes informational questions ("How does calibration work?", "How many jobs have run?") to ATF's `/api/qa` (wiki + operational-ledger RAG), falling back to the existing local-brain chat if ATF is unreachable or has nothing relevant. Draw/write/calibrate-style requests still route to the fast, unchanged local-brain command-JSON path via a lightweight keyword heuristic (no double LLM-call latency for real questions). Verified end-to-end multiple times with real, sourced answers via `ministral-local`. Also switched `control_center.py`'s own chat brain from Apertus to `ministral-3:8b` for consistency.

**Real TTS on chat replies**: chat's spoken output was never actually wired to the backend TTS engine — `speakText()` only ever used the browser's own Web Speech API (hunting for a "Daniel"/"Alex" system voice), completely disconnected from the Kokoro/Voxtral engine setting. Added a `/api/speak` endpoint that invokes `speak.py` server-side (fire-and-forget, plays on the machine's own speakers) and wired chat replies to it instead.

**Wrong-interpreter guard**: `control_center.py` now checks at startup whether it's running under the project venv and relaunches itself under the correct interpreter if not — every subprocess it spawns (`speak.py`, `ai_sketch.py`, `bob_ross.py`) inherits `sys.executable`, so launching under the wrong Python (e.g. double-clicking the `.py` file) silently breaks all of them with missing/stale packages. This had already caused two separate real bugs this week (broken sketch generation on 2026-07-09, broken Voxtral TTS today) before being traced to this root cause. Note: implemented with `subprocess.Popen` + `os._exit`, not `os.execv` — `os.execv` does not reliably replace the process on Windows and was observed leaving a stale second listener bound to the same port (`HTTPServer` allows address reuse), silently splitting requests between the correct and broken interpreter.

**UI**: added Wiki/Ledger Dashboard link buttons (real `<a>` tags, not `window.open()` — more reliable, `window.open()` was the actual cause of an earlier "black background" report). Narrowed the Drawing Command column, widened Talk to Ross to take the flexible remaining space. `launch_control_center.bat` now also starts the ATF Q&A server in its own window (skips it if port 8771 is already listening).

**Real bug found + fixed**: the sketch-status poller used one shared global timer variable across potentially-overlapping poll loops (e.g. from retried Preview clicks) — a loop could clear a *different, newer* loop's timer instead of its own, leaving itself orphaned and firing its "sketch generation failed" message every 2s forever. Each poll loop now tracks its own generation number and can only ever stop itself.

**Known issue, deferred by user to a future session**: Voxtral voice output sometimes cuts off mid-sentence during chat replies. Not yet investigated.
