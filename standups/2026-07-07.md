### FLOT-105: Session manager — rolling context compression

**Task:** 1ooj6p2hpvsvfvj → peer_review. Branch: task/1ooj6p2hpvsvfvj. Commits: 5261dafc (WORKLOG), 896ab6c9 (implementation).

**Deliverable:** `eval/session_manager.py` (168 lines).

**Design:**
- Tier 1 (`_cache: dict[str, entry]`): deterministic citation-ID cache accumulated across turns. Rendered as compact `[id] title` index in the context block. No LLM. Body text never in the cache section — facts always reachable in T1, never only in T2 prose.
- Tier 2 (`_summary: str`): rewritten each turn via a capped Ollama call (`num_predict=200`, `temperature=0.3`) over the last 4 turns. Summarisation prompt explicitly excludes facts/numbers/rule IDs. Falls back to prior summary on LLM error.
- `assemble(query, fresh_hits)` → idempotent ChatML list: `[system:role+grounding]` + `[user: T2 | T1-cache (prior turns) | fresh retrieval (full bodies) | query]`.
- `record(query, response, fresh_hits)`: single state-mutation point — ingests fresh into T1, appends history, refreshes T2.

**Acceptance criteria:**
1. ✅ T1: deterministic citation-ID cache, no LLM.
2. ✅ T2: capped 200-token summary; facts excluded from summarisation prompt; always in T1.
3. ✅ Per-turn reset; assembly order `[role][grounding][summary][citation cache][fresh retrieval(q)][q]`.
4. ✅ 168-line module; runs beside Ollama via stdlib only; multi-turn grounding without window saturation.

**Smoke tests:** turn-0 (no cache, FRESH RETRIEVAL present), turn-1 (CITATION CACHE present, body text excluded from cache section) — all assertions pass.
